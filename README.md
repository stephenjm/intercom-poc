Whilst doing some interview prep I had to prepare for an interview with Intercom.

Part of the process requires you to take a look at their public repo -> https://github.com/intercom/minicom-public/blob/main/spring/README.md
The problem I encountered was that this does not tell me a lot nor does it even mimic what Intercom does at a high level. (What this repo does is create the main Spring service plus two endpoints - one called Foo and another called Bar and there's no interaction among the three).

### For clarity, I did this work prior to my Intercom interview and it's based on the public repo.

The task I put on myself was to attempt to visualise what this company does and then build my interpretation of it.

The work I did was done with the help of AI but, I created the groundwork via the architecture.md 

The result is that you can use Bruno Test suite to create a conversation, add messages, escalate, assign agent and more.

Some nice extras that also present are metrics and audit logs as well as the ability to deploy this via Docker.

Suffice to say I didn't get the offer at Intercom so, no point in you copying this but, it does hopefully show a better picture than that provided on Intercom's public repo.
